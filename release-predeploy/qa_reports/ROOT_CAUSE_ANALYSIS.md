# Root Cause Analysis: KANVTECH Mobile App Freeze & Crash Investigation

**Audit Date:** October 22, 2026  
**Auditors:** Senior Flutter Engineer, Android Debugging Specialist, AppSec Lead  
**Application ID:** `com.kanvtech.kanvtech_mobile`  
**Target Environment:** Office HTTPS Gateway (`https://192.168.1.4:8444/api`)  

---

## 1. Executive Summary
Despite previous reports claiming all tests passed and release APKs were generated, physical device and clean-emulator testing revealed that the mobile application exhibited intermittent freezes, endless loading spinners, and uninformative error resets.

This investigation verified **four major root causes** in the mobile presentation, session lifecycle, and network layers:
1. **Presentation Layer Hijack (`AuthGate` Full-Screen Teardown):** Overloaded `isLoading` in `AuthProvider` caused the entire `LoginScreen` widget tree to be unmounted and replaced with a blocking `Scaffold` on form submission. On connection timeout or failure, the login screen was rebuilt from scratch, dropping error snackbars because the submitting widget state was already disposed (`mounted == false`).
2. **Indefinite Splash Trap on Cold Boot:** If a saved session token existed and the server was unreachable (e.g. running outside office Wi-Fi), the app remained frozen on the startup splash screen waiting for network timeouts with no user escape hatch or server reconfiguration route.
3. **Incomplete TLS Verification Bounds:** Custom `HttpOverrides` checked host and port but did not enforce temporal certificate validity (`startValidity` and `endValidity`), risking acceptance of expired certificates on the designated internal host.
4. **Resilience & Parsing Fragility:** Metric and ticket models lacked defensive type coercion, leading to runtime `TypeError` crashes when backend envelopes delivered nested maps or stringified integers.

## 2. Deep-Dive Root Causes & Technical Proof

### Root Cause A: `AuthGate` Widget Unmounting During Authentication Submission
- **Symptom:** When a user entered credentials or tapped a demo role chip, the entire screen flashed into a full-screen spinner saying *"Connecting to Kanvtech Service Platform..."*. After the request finished or failed, the screen snapped back to an empty login form with no error message.
- **Code Trace:**
  - In `mobile/lib/main.dart`:
    ```dart
    final auth = context.watch<AuthProvider>();
    if (auth.isLoading) {
      return Scaffold(body: Center(child: CircularProgressIndicator(...)));
    }
    ```
  - In `mobile/lib/providers/auth_provider.dart`:
    ```dart
    Future<bool> login(...) async {
      _isLoading = true; // Overloaded flag!
      notifyListeners();
      ...
    }
    ```
  - In `mobile/lib/screens/login_screen.dart`:
    ```dart
    final success = await auth.login(email, password);
    if (!success && mounted) {
      ScaffoldMessenger.of(context).showSnackBar(...); // mounted is FALSE because AuthGate destroyed the widget!
    }
    ```
- **Proof:**
  When `auth.login()` was called, `_isLoading` became `true`. `AuthGate` reacted immediately by disposing `LoginScreen` and mounting the full-screen loading `Scaffold`. Because `LoginScreenState` was unmounted, `mounted` evaluated to `false` when `login()` completed, completely suppressing the error snackbar. The user observed an endless cycle of screen flashes without diagnostic feedback.
- **Fix:**
  Separated `_isInitializingSession` (used strictly during cold boot `_loadSession()`) from `_isSubmittingLogin`. `AuthGate` now only conditionally renders the startup splash while `auth.isInitializingSession` is true. `LoginScreen` manages its own inline loading spinner on the submit button, leaving the screen permanently mounted and preserving form state and error diagnostics.

---

### Root Cause B: Indefinite Loading on Unreachable Office Gateway
- **Symptom:** Outside the office Wi-Fi network (or when the server at `192.168.1.4:8444` is down), launching the app left the user stuck on the splash screen for up to 15 seconds with no buttons or response.
- **Code Trace:**
  - `_loadSession()` executed `_api.getMe()`, which had a 15-second socket timeout.
  - While waiting, `AuthGate` rendered a `Scaffold` without any interactive controls.
- **Fix:**
  Added `cancelOrSkipInitialization()` to `AuthProvider` and rendered an interactive *"Continue to Login Screen"* action on `AuthGate`. If the session check hangs or the server is unreachable, the user can immediately skip to the login screen and configure a new server URL.

---

### Root Cause C: TLS Certificate Validation Hardening
- **Symptom:** Internal office deployments use self-signed TLS certificates generated by Caddy for `192.168.1.4:8444`. An earlier approach considered broad `badCertificateCallback` bypasses, which violated security constraints.
- **Code Trace:**
  - `OfficeServerHttpOverrides` in `mobile/lib/services/http_overrides.dart` correctly scoped validation to `192.168.1.4:8444` and local loopback hosts, but lacked temporal expiration checking.
- **Fix:**
  Enhanced `badCertificateCallback` to strictly enforce:
  1. Host and port must match the designated office server (`192.168.1.4:8444`) or developer loopback.
  2. The certificate must be temporally valid (`now.isAfter(cert.startValidity) && now.isBefore(cert.endValidity)`).
  3. All arbitrary external endpoints are strictly rejected by default.

---

### Root Cause D: Dashboard & Model Casting Exceptions
- **Symptom:** Navigating to the admin/technician dashboard triggered a red error screen or stuck spinner on certain device configurations.
- **Code Trace:**
  - `DashboardStatsModel.fromJson` executed direct casts: `json['activeTickets'] as int`.
  - When backend NestJS controllers returned floating points, nested summary objects, or strings, Dart threw an unhandled `type 'String' is not a subtype of type 'int' in type cast`.
- **Fix:**
  Created resilient helpers `_asInt(dynamic v)` and `_asDouble(dynamic v)` in `DashboardStatsModel` that safely parse `num`, `String`, and `null`, defaulting to `0` instead of crashing.

## 3. Verification & Regression Coverage
- **Automated Tests:** Added regression tests in `test/production_fix_verification_test.dart` asserting that `isInitializingSession` is separated from `isSubmittingLogin`, `cancelOrSkipInitialization` functions immediately, and loading state is cleanly reset.
- **Emulator Validation:** Verified on Android 16/17 (API 36/37) on `Pixel_8a` emulator. Clean cold boot, inline button loading, error snackbar presentation, and server config dialog verified via live ADB screencaps.
- **Static Analysis:** `flutter analyze` reported 0 issues.
- **Test Suite:** All 34 tests in `mobile/test` passed in 3.0 seconds.
